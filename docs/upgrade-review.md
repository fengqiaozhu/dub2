## 本轮已实现

1. **章节交付检查**：新增 `export_readiness`，统计缺失、过期与失败句。工作台禁用未就绪的拼接按钮并提供原因；后台任务再次检查，防止直接调用接口绕过检查。明确跳过的句子不阻塞交付，空章节不能拼接。
2. **旧音轨有效性**：只要当前章节仍有未完成句，旧拼接轨就不能显示为当前版本，避免新增句未配音时误认为可以交付。
3. **拼接顺序**：按正文位置排序音频，避免依赖数据库返回顺序；不修改输入数组。
4. **任务轮询恢复**：短暂断网、服务端错误与限流自动退避重试，最长间隔 30 秒。慢请求不会重叠；停止后不会回写迟到的响应。永久客户端错误与任务终态停止轮询。
5. **任务启动失败**：等待 Bree 启动结果。注册或启动失败时写入 FAILED，清理注册记录，避免任务长期显示 PENDING。
6. **媒体路径**：移除 Express 路由的重复解码；支持对象键中的百分号。损坏的媒体 URL 视为缺失，不能进入拼接。
7. **持续验证**：新增前端轮询测试和 GitHub Actions 验证流程。CI 文件已保存，尚未推送或在 GitHub 上运行。
8. **任务取消（H1）**：新增 `POST/DELETE /api/jobs/:id/cancel`。取消会调用 Bree `remove` 停止 worker，把任务标记为 `CANCELLED`；终态任务幂等返回，未知任务返回 404。迟到的 worker 消息不会把已取消任务改回 RUNNING/DONE/FAILED。前端在工作台提供“停止配音/停止拼接”，在解析页提供“停止解析”，取消后进行中的轮询立即停止。
9. **超时评估（H5）**：`request.ts` 默认 10s 只适合普通 JSON 调用。上传（书文件、封面、音色样本）改为 120s，`dubbing-preview` 这类同步重计算读取改为 60s；任务启动与轮询仍用默认短超时，避免掩盖真正的连接问题。

## 验证结果

- 原始基线：24 项后端测试通过，前端类型检查及生产构建通过。
- 修改后：35 项后端测试、6 项前端测试通过；后端语法检查、前端类型检查与生产构建通过。
- 新增测试覆盖音频完整性、文本/音色变更、跳过、排序、损坏路径、真实 HTTP 路由解码、任务启动失败、任务复用、任务取消（含真实 HTTP 路由）、断网重试、慢请求和停止后响应。
- 依赖使用现有锁文件安装，没有升级依赖版本。安装时禁用了生命周期脚本，测试没有执行真实 ffmpeg 合成。
